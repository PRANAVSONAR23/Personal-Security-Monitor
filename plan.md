# PSM — Plan of Action (Executable)

Solo-developer plan, ~10 weeks part-time. Each phase ends with something runnable. Order is chosen so the highest-value flow (local Windows before/after diff) ships first — the controller platform is now also the first collection target, which removes a whole transport layer from the MVP.

## Phase 0 — Foundations (Week 1)
**Goal: skeleton that stores and verifies data.**
1. Repo setup: Python 3.12 on Windows, `pyproject.toml`, ruff, pytest, pipx-installable entry point `psm`.
2. Implement `store/`: schema from LLD §1, migrations, canonical_json (incl. Windows path normalization), hash chain (`chain.py`), `psm db verify`.
3. Implement core models (`Device`, `Snapshot`, `InventoryItem`, `Event`).
4. Implement diff engine (LLD §4) + property tests: `diff(A,A)==∅`, chain tamper test.
**Exit criteria:** `pytest` green; can insert synthetic snapshots and diff them from a test.

## Phase 1 — Windows Collector, MVP (Weeks 2–3)
**Goal: `psm baseline` + `psm scan` + `psm watch --before-after` working locally on the PC.**
1. Vendor pinned osquery; osquery runner with timeout + JSON parsing.
2. Modules in priority order: persistence (run keys, services, tasks, startup, WMI subs) → apps (programs + Appx) → files (hash walk with mtime/file_id skip) → signatures (authenticode on new/changed executables only) → processes → network (listening_ports + open sockets).
3. Normalizers with golden-file tests (record real osquery output as fixtures).
4. `psm doctor` (elevation check, explains what admin adds) — capability negotiation wired in.
5. CLI: `device add`, `baseline`, `scan`, `watch --before-after`, terminal report rendering.
**Exit criteria:** UC2 works end-to-end: snapshot → install a test app + add a fake Run-key entry → snapshot → both appear as events, run completes < 60 s.

## Phase 2 — Rules, Alerts, Explain (Week 4)
1. YAML rules engine (match + correlate), ship 5 built-in rules from LLD §5.
2. Alerts table + `psm alerts` lifecycle.
3. `psm explain` with templates for the top 8 event types (Run key, service, scheduled task, unsigned exe, etc.).
4. Severity rendering in scan report; exit code 3 on alerts.
**Exit criteria:** planting an unsigned exe in %APPDATA% + a Run-key entry pointing at it produces one correlated alert with a readable explanation.

## Phase 3 — Android Collector (Weeks 5–6)
1. ADB wrapper around bundled/detected `adb.exe`: device detection, timeout handling; `psm doctor` detects unauthorized/offline states and prints OEM-driver guidance.
2. Modules: packages → permissions → special_access (accessibility/device-admin) → downloads → netstats.
3. Version-keyed dumpsys parsers; fixtures from at least Android 13 and 14.
4. Android-specific rules: new accessibility grant, sideloaded install (`source: sideload`).
**Exit criteria:** `psm baseline android` + install an APK + grant a permission → `psm scan android` shows exactly those events.

## Phase 4 — macOS Collector Shim (Week 7)
1. Write `psm_mac_collector.py` (single file, stdlib-only): apps, persistence (launchd/login items/cron), TCC permissions, hash walk, codesign checks, lsof, browser, processes.
2. Transport: `psm scan mac --ssh user@host` (pipe shim over SSH, read JSON stdout) and `psm ingest macos FILE` for manual mode.
3. `collector.schema.json` + validation on ingest; `psm doctor mac --ssh …` verifies reachability and TCC readability, with documented FDA setup steps.
4. Fixtures + normalizer tests from real shim output.
**Exit criteria:** from the Windows PC, `psm baseline mac --ssh …` then add a LaunchAgent on the Mac → `psm scan mac --ssh …` shows it as a persistence event.

## Phase 5 — Timeline, Reports, Browser (Week 8)
1. Timeline query + `--export jsonl` (Timesketch-compatible field mapping).
2. `psm report daily` + Task Scheduler XML sample for scheduling.
3. Browser module (Windows + macOS shim): extensions with permission manifests, downloads — Chrome, Edge, Firefox, Safari.
4. Browser rules: new extension with `<all_urls>`.
**Exit criteria:** 7-day timeline renders; daily report generated by Task Scheduler; installing an Edge/Chrome extension surfaces an event.

## Phase 6 — Enrichment & Hardening (Week 9)
1. `known_good_hashes` import (user-supplied list, OS-baseline capture command).
2. Optional VT hash-only lookup (`--enrich vt`), strictly opt-in.
3. Size/timeout limits audit, schema validation on all collector input, fuzz the macOS shim-JSON ingester.
4. `psm db export --signed` (minisign detached signature) — stretch.
**Exit criteria:** malformed/hostile shim JSON cannot crash or corrupt; enrichment labels known-good files in reports.

## Phase 7 — Polish & Release (Week 10)
1. README, quickstart per platform, threat-model doc, permission-setup guides (UAC/elevation, Mac FDA + Remote Login, Android USB debugging + drivers).
2. Package: pipx instructions on Windows, shim published as a standalone file in releases.
3. Dogfood for a week; fix the top annoyances; tag v1.0.

## Working Agreements
- Every module lands with fixtures + tests in the same PR.
- No feature starts before its exit criteria are written in todo.md.
- Layer 2 items (ETW, WFP, Sysmon ingest, FSEvents daemon, VPN, proxy) are not begun until v1.0 is tagged.

## Definition of Done (v1)
UC1–UC5 from HLD §4 all work on real hardware (1 Windows PC as controller, 1 Mac, 1 Android phone), `psm db verify` passes after a month of dogfooding, and a stranger can set it up from the README alone.
